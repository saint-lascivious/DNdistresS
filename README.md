## description

```text
Topic: description

DNdistresS continuously (or time-bounded) sends DNS a configurable volume of 
queries of any type from a prepared domain top domains list and/or custom list,
using token-bucket scheduling and a worker pool.

Whether it's a trickle of queries or a flood, in bursts or at a constant rate,
on demand or as a periodic background task, with dig or nslookup, DNdistresS
is designed to generate controlled DNS traffic for cache priming, testing,
benchmarking, or otherwise simulating workloads against resolvers.

Key properties:
  - Deterministic rate shaping via qps + burst
  - Parallel execution via worker pool
  - Flexible domain source handling (download/cache/file/custom list)
  - Resolver targeting (local/remote, IPv4/IPv6, port)
  - Query tool selection (dig/nslookup) and RR type selection

DNdistresS is an impractically complex resolver workload tool for controlled DNS
traffic generation.
```

## auto-tune

```text
Topic: auto-tune

Meaning:
  Auto-derive worker count (_MAXIMUM) and burst size (_BURST) before the main
  run.

Enable:
  --auto-tune

Defaults:
  _AUTO_TUNE_SAMPLES=10
  _AUTO_TUNE_BURST_WINDOW_MS=250
  _AUTO_TUNE_TRIM_PCT=10
  _AUTO_TUNE_PERCENTILE=95
  _AUTO_TUNE_PCTL_MAX_RATIO=4
  _AUTO_TUNE_MAX_GROWTH_FACTOR=5

Sample-count selection:
  - _AUTO_TUNE_SAMPLES is the base sample count.
  - If both _AUTO_TUNE_SAMPLES_MIN and _AUTO_TUNE_SAMPLES_MAX are set to valid
    positive integers and MAX >= MIN, sample count is randomised uniformly in
    [MIN, MAX].
  - If only one of MIN/MAX is set, range mode is ignored and
    _AUTO_TUNE_SAMPLES is used.
  - Sample count is clamped to available domain count when necessary.

Warmup domain selection:
  - Warmup domains are selected randomly (without replacement) from the active
    domain pool, not taken from the head of the list.
  - Active pool means domains after parsing/validation, deduplication, and
    active top/filter selection.

Mechanism:
  1) Warmup:
     Run a short synchronous probe over randomly selected sample domains.
  2) Estimate:
     - collect latency samples (ms)
       (per-query in non-batch mode, per-batch when dig batching is active)
     - trim low/high outliers by _AUTO_TUNE_TRIM_PCT
     - compute median (p50) and target percentile (_AUTO_TUNE_PERCENTILE)
     - cap percentile to: pctl_ms <= p50_ms * _AUTO_TUNE_PCTL_MAX_RATIO
  3) Derive:
     batch_effective = (_DIG_BATCH_SIZE_EFFECTIVE when dig batching is active, else 1)
     _MAXIMUM ~= ceil((_QPS / batch_effective) * (pctl_ms/1000) * 1.2)
     _BURST   ~= ceil(_QPS * (_AUTO_TUNE_BURST_WINDOW_MS/1000))
     if batch_effective > 1:
       - _BURST is raised to at least batch_effective
       - _BURST is rounded up to a multiple of batch_effective
  4) Guard:
     tuned workers per run are capped to:
       current _MAXIMUM * _AUTO_TUNE_MAX_GROWTH_FACTOR
     (unless --force-maximum / -m N! is set)

You want I should give 'em the clamps?
  - If -m N! or --force-maximum is set, auto-tune will not change _MAXIMUM.
  - If -B N! or --force-burst is set, auto-tune will not change _BURST.
  - Baseline floor: without force overrides, auto-tune will not reduce
    _MAXIMUM/_BURST below their current configured values; it only raises
    them.
  - Standard safety clamps are applied after auto-derived values.
  - Ooh, that's gotta clamp!

Notes:
  - Auto-tune is best-effort and depends on current resolver/network/host
    conditions and how much I suck at writing selection algorithms.
```

## dig-options

```text
Topic: dig-options

Meaning:
  Passes custom arguments to dig for query execution.

Flag:
  --dig-options DIG_ARGS...
  --dig-options="DIG_ARGS..."

Default:
  +short +time=1 +tries=1 +retry=0 +notcp +ignore

Mode:
  _DIG_OPTIONS_MODE=append
  append  => default bundle + user bundle
  replace => user bundle only

Behaviour:
  - Captures tokens after --dig-options until the next valid DNdistresS option
    or end-of-command.
  - Applies only when _BINARY=dig (or auto resolves to dig).
  - Effective args are mode-dependent, then +short is always enforced at tail.
  - If auto resolves to nslookup, options are ignored with warning by default;
    set _STRICT_DIG_OPTIONS=1 to fail instead.
  - Rejects conflicting dig tokens that alter DNdistresS owned query shape/
    transport: @server, -p, -q, -t, -x, -f.

Important:
  Some dig flags overlap with DNdistresS option tokens (e.g. -p, -q, -t).
  In those cases, prefer the quoted '=' form so arguments stay grouped.

Examples:
  --dig-options +time=2 +tries=1 +retry=0 +notcp +ignore
  --dig-options="+dnssec +bufsize=1232"
  --dig-options-mode replace --dig-options="+time=2 +tries=2"
```
